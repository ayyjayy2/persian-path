# Move to Firebase: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace Supabase (sign-in, sync) and Netlify (hosting) with Firebase Auth, Firestore and Hosting, so nothing pauses and deploys are unlimited.

**Architecture:** One new module, `backend.js`, is the only file that talks to Firebase. It wraps a vendored ESM bundle of the Firebase SDK (`vendor/firebase.js`, built once with esbuild and committed). `app.js` keeps its sync flow and swaps the Supabase calls for `backend.js` calls. A pure `auth-messages.js` turns Firebase error codes into plain wording, and Node tests it. Hosting is `firebase.json`, deployed by two GitHub Actions: live on merge to `main`, a preview channel per PR.

**Tech Stack:** Preact + htm (vendored, no build step), Firebase JS SDK 13.1.0 (`app`, `auth`, `firestore/lite`), esbuild 0.28.2 (dev only), Firebase CLI 15.8, gcloud, GitHub Actions with `FirebaseExtended/action-hosting-deploy@v0`.

**Spec:** `docs/superpowers/specs/2026-10-31-firebase-design.md`

**Facts you need:**
- **Firebase project:** `persian-learnin`. Email/Password sign-in is enabled and Firestore exists (Standard edition, nam5). The web app is registered; print its config with `firebase apps:sdkconfig WEB --project persian-learnin`.
- **Accounts on this Mac:** the `firebase` CLI and `gcloud` are both logged in as alaynajohnston12@gmail.com, an Owner of the project.
- **Branch:** `PER-42-firebase`, cut from `PER-41-sync`.
- **Never stage** `Persian Learning App Revamp.zip` or `scripts/list-missing.js`.
- **Rebuild the precache list:** rerun `node scripts/build-precache.js` before every commit that touches app files.
- **Pushing:** ask the user before every push.
- **Browser tests:** mute audio.
- **Real account actions (sign-up, sign-in):** do not create accounts or enter credentials in the browser. The user does the sign-in tests (Task 8).
- **Keep `netlify.toml` for now** (a change from the spec). Netlify builds this code once more at merge time, so devices can upload their progress from the old address. It's removed after the cutover.

```js
// Firebase sign-in errors in plain words. Pure, so Node can test it (scripts/test-auth-messages.mjs).
const OFFLINE = "You're offline. Sign in once you're connected — your progress is saved on this device meanwhile.";
const WRONG = 'Wrong email or password.';
const MESSAGES = {
  'auth/invalid-credential': WRONG, 'auth/invalid-login-credentials': WRONG, 'auth/wrong-password': WRONG, 'auth/user-not-found': WRONG,
  'auth/email-already-in-use': 'That email already has an account. Sign in instead.',

  'auth/invalid-email': 'Check the email address.',
  'auth/network-request-failed': OFFLINE,
  'auth/too-many-requests': 'Too many tries. Wait a minute and try again.',
};

export function authMessage(err) {
  return (err && MESSAGES[err.code]) || (err && err.message) || 'Something went wrong. Try again.';
}
```

### Task 3: `backend.js`, the only file that talks to Firebase

**Files:**
- Create: `backend.js`

- [ ] **Step 1: Write the module**

Use the config from `firebase apps:sdkconfig WEB --project persian-learnin`. Like the Supabase publishable key it replaces, the web config is public by design; the Firestore rules (Task 5) are what protect the data.

`backend.js`:

```js
// Sign-in and each learner's synced document, on Firebase. The only file that talks to Firebase;
// app.js decides what to sync and sync.js how to merge it.
import {
  initializeApp, initializeAuth, indexedDBLocalPersistence, browserLocalPersistence, onAuthStateChanged,
  signInWithEmailAndPassword, createUserWithEmailAndPassword, signOut, getFirestore, doc, getDoc, setDoc,
} from './vendor/firebase.js';

const app = initializeApp({
  apiKey: 'AIzaSyDWQMtoMoOUOxBzl_85f3PKZmNhe6N8mb8',
  authDomain: 'persian-learnin.firebaseapp.com',
  projectId: 'persian-learnin',
  storageBucket: 'persian-learnin.firebasestorage.app',
  messagingSenderId: '573429612507',
  appId: '1:573429612507:web:8902d4c4fa88ff2097b1fe',
});
// Stay signed in across app opens; fall back to localStorage where IndexedDB is unavailable
const auth = initializeAuth(app, { persistence: [indexedDBLocalPersistence, browserLocalPersistence] });
const db = getFirestore(app);
const userDoc = id => doc(db, 'users', id);

// The app only needs these two fields; keep Firebase's User object out of Preact state
const toUser = u => (u ? { id: u.uid, email: u.email } : null);

// Calls back with the signed-in user (or null) now and on every change
export const onUser = cb => onAuthStateChanged(auth, u => cb(toUser(u)));
export const signIn = (email, password) => signInWithEmailAndPassword(auth, email, password);
// Signs the new account in straight away (no email confirmation)
export const signUp = (email, password) => createUserWithEmailAndPassword(auth, email, password);
export const signOutUser = () => signOut(auth);

// The user's synced fields, or null before their first upload
export async function loadDoc(id) {
  const snap = await getDoc(userDoc(id));
  return snap.exists() ? snap.data() : null;
}
// Replaces the whole document. The JSON round trip drops undefined values, which Firestore rejects.
export const saveDoc = (id, data) => setDoc(userDoc(id), JSON.parse(JSON.stringify(data)));
```

- [ ] **Step 3: `firebase.json`**

Every file gets `Cache-Control: no-cache`, matching Netlify's default (always revalidate). Firebase's default is an hour of browser caching. With that, the service worker could precache a stale `app.js` under a new version, because `cache.addAll` goes through the HTTP cache.

```json
{
  "hosting": {
    "public": ".",
    "ignore": [
      "firebase.json", "firestore.rules", "netlify.toml", "README.md", "package.json", "package-lock.json",
      "**/.*", "**/node_modules/**", "docs/**", "scripts/**", "*.zip", "firebase-debug.log"
    ],
    "predeploy": ["node scripts/build-precache.js"],
    "headers": [
      {
        "source": "**",
        "headers": [
          { "key": "Cache-Control", "value": "no-cache" },
          { "key": "X-Frame-Options", "value": "DENY" },
          { "key": "X-Content-Type-Options", "value": "nosniff" },
          { "key": "Referrer-Policy", "value": "strict-origin-when-cross-origin" }
        ]
      }
    ]
  },
  "firestore": { "rules": "firestore.rules" }
}
```

```markdown
## Deploying

The site is on Firebase Hosting at <https://persian-learnin.web.app> (Firebase project `persian-learnin`).

- **Live:** every push to `main` deploys (`.github/workflows/firebase-hosting-merge.yml`). There's no deploy limit, so merge whenever a change is ready.
- **Previews:** every PR gets its own preview URL, posted as a comment on the PR (`.github/workflows/firebase-hosting-pull-request.yml`).
- **Both workflows** run `node scripts/build-precache.js` first, and authenticate with the `FIREBASE_SERVICE_ACCOUNT_PERSIAN_LEARNIN` secret (service account `github-deploy`).
- **Firestore rules** don't deploy with the site. After changing `firestore.rules`, run `firebase deploy --only firestore:rules`.
- **Manual deploy, if ever needed:** `firebase deploy --only hosting`.

The app used to be on Netlify (persian-learnin.netlify.app) with Supabase. See [the Firebase move](docs/superpowers/specs/2026-10-31-firebase-design.md) for why it moved and how devices moved their progress.
```
